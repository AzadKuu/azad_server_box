# 2026-08-28

## 鸿蒙终端：软键盘自动切英文 / 禁止首字母大写 — 可行性调研

**问题**：App 内 SSH 终端页（`lib/view/page/ssh/page/page.dart`，用 `packages/xterm` 的
`TerminalView` + `CustomTextEdit`）在鸿蒙手机上唤起系统软键盘时，默认是中文输入法且
首字母自动大写，打命令很难受。问能否在进入终端时自动切英文输入法并关闭首字母大写。

**结论：两个都做不到，鸿蒙 IME Kit 没有对外开放的对应能力。**

调研到的关键事实（查了本地 SDK `D:\Program Files\Huawei\DevEco Studio\sdk\default\openharmony\ets\api\@ohos.inputMethod.d.ts`）：

1. `inputMethod.InputAttribute`（SDK d.ts 1650 行）**只有 5 个字段**：
   `textInputType`、`enterKeyType`、`placeholder?`、`abilityName?`、`consumeKeyEvents?`。
   **没有任何**控制大小写/自动大写的字段（无 `capitalInputMode`、无 `textCapitalization`）。
   → 无法禁止首字母大写。

2. `inputMethod.switchInputMethod(target)`（d.ts 114/130 行）明确要求
   **"The caller must be the current inputmethod"**，且需要
   `ohos.permission.CONNECT_IME_ABILITY`（9~10 版本），三方普通 App 拿不到。
   → 无法自动切换输入法。

3. 切换「中英输入状态」属于**输入法内部的 subtype / 私有状态**。
   `InputMethodSubtype` 相关 API（`getCurrentInputMethodSubtype`、`listInputMethodSubtype`）
   是给输入法自身或系统设置用的，三方 App 无法写入/切换。

**根因补充（为什么 Flutter 侧设了也没用）**：
`packages/xterm/lib/src/ui/custom_text_edit.dart:392` 其实已经写了
`textCapitalization: TextCapitalization.none`、`autocorrect: false`。
但 flutter_ohos 引擎的 `TextInputChannel.ets` 的 `Configuration` 类**根本没有
textCapitalization / autocorrect 的解析落到 InputAttribute**，只有
`textInputType` 和 `enterKeyType` 会被传给 `inputMethod.InputAttribute`
（`TextInputPlugin.ets` 683-684、1216-1217 行）。
所以 Dart 侧这些配置在鸿蒙上**被静默丢弃**。

**可行的替代方案（未实施，用户尚未确认）**：
- 在 `onInsert` 回调里把输入的大写字母转小写后再喂给终端（治标，且会破坏
  有意的大写输入如 `Sudo`、`PATH`）。
- 终端页提供提示，引导用户手动切英文键盘。
- 依赖输入法自身对 `TextInputType.TEXT`/终端场景的处理。

**既有相关设施**：
- `lib/core/utils/ohos_ime.dart` + `EntryAbility.ets` 的 `azad/ime` channel 已解决
  退格键问题（监听 `deleteLeft`）。同一套 channel 机制可扩展，但大小写/输入法切换
  无原生 API 可依托。

## 真正确认的根因（用户指出，重要）

首字母自动大写**不是输入法凭空的行为**，而是退格键修复的副作用：

`packages/xterm/lib/src/ui/custom_text_edit.dart:419-429` 的 `_initEditingState`：
- 鸿蒙分支初始编辑状态是 `text: ' '`（一个空格）、`selection: collapsed(offset: 1)`，
  注释写着 "One space to avoid (0,0) selection on OHOS"。
- 这是为了让 `TextInputPlugin.handleDeleteEvent` 不因选区为 (0,0) 而忽略退格。
- 副作用：**光标前面有字符 → 输入法判定为"句中" → 从第二个字母起自动大写**。

即：退格可用 与 首字母不大写 在当前方案下是互斥的。

- `lib/view/page/ssh/page/init.dart`：新增 `_showImeHint()`，复刻 `_showHelp()` 的
  `showRoundDialog` + "不再提示" 模式；在 `page.dart` 的 `afterFirstLayout` 中
  于 `_showHelp()` 之后、`_initTerminal()` 之前调用。
- `lib/core/utils/ohos_ime.dart`：新增 `deviceType()` 与 `isDesktop()`（2in1/pc）。

## 重要：不要动 isMobile 的 2in1 判定

`EntryAbility.ets` 的 `isMobile = phone || tablet || 2in1` —— **2in1 必须保留在内**。
鸿蒙 PC/2in1 在平板模式或触屏使用时同样弹软键盘，同样依赖 `azad/ime` 退格兜底。
（我曾误改成把 2in1 排除，被用户纠正后已还原。）

ArkTS 侧只新增了一个**只读**的 `deviceType` method 分支用于 UI 文案分支，
不影响退格 handler 注册逻辑。UI 侧区分桌面/移动请用 `OhosIme.isDesktop()`，
不要用 `isMobile()`（后者语义是"需要软键盘兜底"）。
